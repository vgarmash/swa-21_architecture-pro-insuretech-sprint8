# Задание 4. Проектирование продажи ОСАГО

## Решение

**Детали реализации osago-aggregator:**

1. **База данных**  
   Сервису не требуется, так как запросы выполняются быстро и нет необходимости в долгосрочном хранении данных.

2. **API**  
   Как ранее было определено командой, в качестве API будут использоваться:
    - Потоки команд для запросов к сервисам страхования,
    - Topic с предложениями от страховых компаний.

3. **Интеграция core-app и веб-приложения**  
   Для обеспечения двунаправленной связи и оперативного получения предложений от страховых компаний потребуется внедрить **gRPC API**.

4. **Паттерны отказоустойчивости**
    - **Для запросов к страховым компаниям** — `Timeout`, `Retry`, `Rate Limiter` (для соблюдения контракта внешней интеграции).
    - **Для заявок на ОСАГО** — `Circuit Breaker`, `Timeout`, `Retry`.
    - **Для запросов из веб-приложения в core-app** — `Timeout`.
    - **Для запросов от систем партнеров** — `Circuit Breaker`, `Timeout`, `Retry`.
