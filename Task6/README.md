# Задание 6. Настройка Rate Limiting

## Описание задачи

Количество запросов от одного из партнеров всё ещё снижает производительность приложения. Это влияет на опыт использования API других партнеров. Для решения этой проблемы необходимо внедрить ограничение частоты запросов (Rate Limiting).

## Реализация

Конфигурационный файл Nginx с ограничением частоты запросов:

### Конфигурация

```nginx
http {
    # Настройка upstream для балансировки нагрузки
    upstream backend_servers {
        server backend1.example.com;
        server backend2.example.com;
        server backend3.example.com;
    }

    # Ограничение частоты запросов
    limit_req_zone $binary_remote_addr zone=api:10m rate=10r/m;

    server {
        listen 80;
        location / {
            limit_req zone=api burst=5 nodelay;
            proxy_pass http://backend_servers;
        }
    }
}
```

### Описание параметров

1. **`limit_req_zone`** - создает зону ограничения частоты:
   - `$binary_remote_addr` - использует IP-адрес клиента для идентификации
   - `zone=api:10m` - создает зону с именем "api" размером 10 мегабайт
   - `rate=10r/m` - устанавливает лимит в 10 запросов в минуту

2. **`limit_req`** - применяет ограничение к запросам:
   - `zone=api` - использует созданную зону ограничения
   - `burst=5` - позволяет обрабатывать сразу 5 запросов сверх лимита
   - `nodelay` - не откладывает запросы, а сразу возвращает ошибку при превышении лимита

### Результат

- Каждый уникальный IP-адрес ограничен 10 запросами в минуту
- При превышении лимита клиент получает HTTP-ошибку с кодом 429 (Too Many Requests)
- Это предотвращает перегрузку системы одиночным партнером
- Обеспечивает справедливое распределение ресурсов между всеми партнерами
